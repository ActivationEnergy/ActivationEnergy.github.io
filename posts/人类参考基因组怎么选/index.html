人类参考基因组怎么选

2026年10月2日
18 分钟
8730 字
Categories: Tech
Tags: Bioinf

TLDR

  • 要提取序列，用hg19.p13和hg38.p14
  • 要做alignment，用hs37d5和NCBI no_alt_plus_hs38d1_analysis_set

参考基因组，对于做测序相关的数据分析工作来讲，是非常基本、非常常用的一个数据，甚至可能是天天用的。但即便如此，人类参考基因组怎么选也并不显而易见，有很多复杂的细节需要考虑，尤其是提取序列与比对 reads 还是两个不同的问题，所以今天就把相关的内容总结一下。

同样叫“hg38”的文件，可能包含不同的染色体、替代单倍型(alt)、修补序列(fix)和decoy，也可能把一些区域的碱基写成N(mask)。这对两类任务的影响不同：

  • 按坐标提取序列，首先要找到坐标所属的那条序列，并且必须是完整的未mask的序列；
  • 将测序 reads 比对到参考，则要考虑整套序列如何影响比对质量和后续变异检测。

先理解 primary、ALT 和 FIX

可以把组装想成一张地图：primary 是主干及暂时无法放到主干确切位置的片段；ALT 是同一局部的另一种表示；FIX 是对局部已知问题给出的修正序列。它们不是三套彼此独立的完整人体基因组。 GRC 术语表：“Primary Assembly”“Alternate locus”“Genome Patch”

Primary 不只含 1～22、X、Y。 GRC 所说的 primary assembly unit 是一套尽量不重复的单倍体表示，包含以下三类核基因组序列：

Primary 内的序列 含义 GRCh38 的 UCSC 名称示例
assembled chromosomes 已组装到染色体坐标上的 1～22、X、Y；chr17:1000 属于此类。 chr17
unlocalized scaffold 知道它属于哪条染色体，却尚不知道在该染色体上的准确顺序或方向；其坐标仍属于 scaffold 本身。 chr17_GL000205v2_random
unplaced scaffold 连属于哪条染色体也未能确定；同样拥有自己的 scaffold 坐标。 chrUn_GL000220v1

这些示例确实出现在 NCBI GRCh38.p14 assembly report 的“Assembly-Unit”列 ，前两种 scaffold 分别标为 unlocalized-scaffold、unplaced-scaffold，并同属 Primary Assembly。 GRC 术语表：“Primary Assembly”“Unlocalized Sequence”“Unplaced Sequence”

人类 FASTA 往往也收录线粒体 chrM，但它在上述 NCBI 组装报告的正式 Assembly-Unit 分类中是 non-nuclear，不是核基因组 primary。chrEBV 和人工 decoy 则是某些 analysis set 加入的比对目标，也不因此变成 GRC primary。实际用软件时应查看 .fa或.fai，不要仅凭“primary”这个简称猜测是否含 chrM。另外，hs37d5里面包含的是chrMT，hg19里面是chrM，这两个不一样，长度上前者短了2个bp。现在公认的应该是chrMT参考序列应该是rCRS NC_012920 这个版本，所以hg19.p13里面也用了这个，后面有详细介绍。 NCBI GRCh38.p14 assembly report：“non-nuclear”单元与 MT 行 UCSC hg38 README.txt：“Analysis set”节

ALT 是局部替代表示。 例如 chr6_GL000250v2_alt 提供 chr6 某个复杂区域的另一条序列路径；它不是另一整条 chr6。不同 ALT 可能代表不同单倍型及结构差异，ALT 的存在也不意味着 primary 有错误。初始 GRCh38 已有 ALT；后续 patch release 增加的 NOVEL patch 将在下一次 major release 归入替代位点。由于 ALT 与 primary 可共享较长的相似序列，直接把两者交给不理解 ALT 关系的比对流程会产生竞争性比对。 UCSC hg38 README.txt：“Sequence names”节的“Alternate loci scaffolds”段 、 GRC：“What types of patches are there?”节

FIX 是局部修正，不是对原染色体文件的原位改写。 例如 chr9_KN196479v1_fix 对应 ABO 区域的修正表示。一个 FIX 可以改变局部碱基、填补缺口或调整组装路径，也会包含与 primary 重复的锚定序列。它有自己的坐标；GRCh38.p14 发布 FIX 后，原有 chr9 坐标保持不变。GRC 建议解释这个位点时考虑 FIX，但把所有 FIX 无条件加入常规比对参考会引入额外的重复定位。 GRC：“What types of patches are there?”中的 ABO 图例及“What implications do patches have for my analyses?”节

用组装单元表示，三者的关系是：

TEXT 
GRCh38.p14
├─ Primary Assembly：主染色体 + unlocalized + unplaced
├─ ALT_REF_LOCI：major release 中已有的局部替代序列
├─ PATCHES：累积的 FIX 与 NOVEL patch
└─ non-nuclear：线粒体序列
GRCh38.p14 ├─ Primary Assembly：主染色体 + unlocalized + unplaced ├─ ALT_REF_LOCI：major release 中已有的局部替代序列 ├─ PATCHES：累积的 FIX 与 NOVEL patch └─ non-nuclear：线粒体序列

上述层级描述的是 GRC 组装的组成；analysis set 还会从中选取、遮蔽或额外加入序列。UCSC 常用 _alt、_fix 后缀，NCBI 则使用 NW_...、NT_... 等 accession。查转录本时应核对具体 scaffold 名称，不能直接把 NCBI accession 当作 UCSC FASTA 的序列名。 GRC 术语表：“Assembly Units”“PATCH” UCSC hg38 README.txt：“Sequence names”节

任务一：按基因组坐标提取序列

GRCh37／hg19

FASTA 序列组成与用途
UCSC hg19.fa.gz 初始 GRCh37；可用于明确采用原始 UCSC hg19 序列名和坐标的资料，不含后来加入的 p13 patch。
UCSC hg19.p13.plusMT.fa.gz 在原有 hg19 序列之外增加 GRCh37.p13 patch，并增加 rCRS 线粒体 chrMT。需要提取 p13 FIX／ALT 坐标时，先检查它的 .fai。
human_g1k_v37.fasta.gz／hs37d5.fa.gz 1000 Genomes 的 GRCh37 分析参考，后者增加 decoy 和 EBV；适合与相应比对数据配套，但不能据此推断含有 UCSC p13 的 FIX scaffold。

UCSC 顶层下载目录仍保存初始 hg19 文件；latest/ 指向 p13.plusMT/。目录名称会直接决定一个坐标能否在 FASTA 中找到。 UCSC hg19 README.txt：“Overview”“Patches to hg19”两节 、1000 Genomes 的参考组装说明

线粒体名称不能凭印象判断。 直接核对 UCSC 的 顶层 hg19.chrom.sizes 、p13.plusMT 长度文件 与 latest 长度文件 ，结果如下：

UCSC 长度文件 chrM chrMT
hg19.chrom.sizes 16,571 bp 无
p13.plusMT/hg19.p13.plusMT.chrom.sizes 16,571 bp 16,569 bp
latest/hg19.chrom.sizes 16,571 bp 16,569 bp

后两份长度文件逐字节相同。本地下载的 hg19.p13.plusMT.fa.fai 也得到相同的两条记录。UCSC 说明：chrM 保留早期 hg19 使用的 NC_001807；chrMT 对应后来加入的 rCRS NC_012920。所以，如果“正确”是指现代常用的 rCRS 长度 16,569 bp，在这套 UCSC p13 文件中应选 chrMT。两条记录是不同的参考序列，不能仅因长度相差 2 bp 就把它们当作只相差两处碱基。分析 mtDNA 时要与变异命名和下游资源采用的参考保持一致。UCSC hg19 README.txt：“Differences from the NCBI files”节的线粒体段

GRCh38／hg38

FASTA 序列组成与用途
UCSC hg38.fa.gz 初始 GRCh38，含初始 ALT，但不含后来 p14 加入的 FIX。
UCSC hg38.p14.fa.gz GRCh38.p14 的 UCSC 文件；提取 p14 FIX／ALT 上的目标序列时可用。
UCSC hg38.analysisSet.fa.gz UCSC 提供的 GRCh38 no-alt analysis set，适合与它配套的常规 reads 比对流程。UCSC 说明其序列与 NCBI GCA_000001405.15_GRCh38_no_alt_analysis_set.fna.gz 对应，主要另有重复序列的大小写标记差别；按 no-alt 分析集的设计，它不收录后续独立发布的 p14 FIX scaffold。
NCBI no_alt_analysis_set，常简称 hs38 不含 ALT／patch 的 major-release 分析集，是常规 GRCh38 线性比对的常见起点。
NCBI no_alt_plus_hs38d1_analysis_set 在 no-alt 分析集上增加 hs38d1 decoy；是否采用取决于整条 pipeline。
NCBI full_plus_hs38d1_analysis_set 含 major-release ALT 和 decoy，需要审查比对器及下游是否能正确处理 ALT。

hg38.analysisSet.fa.gz 缺少 p14 FIX 不是文件缺陷：patch 另占一条 scaffold，若直接加入普通比对参考，会与主染色体争夺相似 reads。GRC patch release 不改变原有主染色体坐标，所以该 no-alt 文件仍可作为常规 GRCh38 比对参考；若要按 chr..._fix 的名称和坐标提取修正区域，则应另用包含该 FIX 的 p14 FASTA。UCSC 注明本目录的原始 analysis set 文件不再更新，选用时还要与项目的比对软件、注释和变异资源保持一致。 UCSC hg38 analysisSet/README.txt：首段与“Files included”节 、GRC patches：“What implications do patches have for my analyses?”节

UCSC p14 文件还有一处细节：旧 FIX chr11_KQ759759v1_fix、chr22_KQ759762v1_fix 已分别被 v2 取代，在 NCBI 官方 GRCh38.p14 组装报告中只列 v2。UCSC 为维持已有浏览器表格和数据文件的兼容性，仍在其 p14 FASTA／浏览器数据中保留 v1，并从 chromAlias 中移除旧版本。这说的是两条附加 FIX scaffold 的版本管理，不是 chr11 或 chr22 主染色体失效；新设计应核对并使用目标注释实际对应的 scaffold 版本。UCSC hg38 README.txt：“Files”节后的“Dropped in Genbank and Refseq official releases patch14”段 、NCBI GRCh38.p14 assembly report 的 KQ759759.2／KQ759762.2 记录

T2T／CHM13

T2T-CHM13 是人类参考基因组最新的一套组装， 它解决了 GRCh38 中许多缺口和难以组装的重复区域。早期 CHM13v1.1 没有 Y；v2.0 加入由 HG002／NA24385 样本完成的 Y 染色体。因此，“CHM13v2.0”也不能理解成全部染色体都来自 CHM13 细胞系。它仍是一条线性参考路径，不能代表人群中所有 HLA、KIR 等单倍型。 T2T 项目：“Latest assembly release”节 、T2T 染色体 Y 研究

要区分 组装序列的发布文件 和 为比对准备的 analysis set：

文件 实际内容 典型用途
NCBI GCA_009914755.4_T2T-CHM13v2.0_genomic.fna.gz GenBank 组装 FASTA，以 accession 命名序列。 需要 NCBI accession／组装记录对应关系时。
UCSC hs1.fa.gz UCSC 的 CHM13v2.0 FASTA，以 chr* 命名，并按 UCSC RepeatMasker／TRF 结果 soft mask。 使用 UCSC hs1 注释、浏览器坐标或按这些名称提取序列。
T2T analysis_set/chm13v2.0.fa.gz T2T 发布的 chr* 命名、按项目重复序列模型 soft mask 的 v2.0 FASTA；仍保留 Y-PAR 序列。 需要这套项目参考、且不希望遮蔽 Y-PAR 时。
T2T analysis_set/chm13v2.0_maskedY.fa.gz 在上一种表示的基础上将 Y 染色体 PAR 硬遮蔽为 N。 常规比对中希望避免 X／Y PAR 重复定位时。
T2T analysis_set/chm13v2.0_maskedY_rCRS.fa.gz 除 Y-PAR hard mask 外，还把线粒体替换成 rCRS（NC_012920.1）。 短读长变异分析中常用的 CHM13 起点；Li Heng 的 chm13v2 指向此文件。
T2T analysis_set/chm13v2.0_noY.fa.gz 不含 HG002 的 Y，只保留来自 CHM13 细胞系的序列。 CHM13 细胞系自身的组装比较；不宜误作包含 Y 的通用参考。

以上文件说明分别见 UCSC hs1/bigZips/README.txt：“Files”节 、T2T analysis_set/README.txt：“File descriptions” 及 T2T 项目：“Analysis set”节 。UCSC hs1.chrom.sizes.txt 列出 25 条序列，其中 chrY 长 62,460,029 bp、chrM 长 16,569 bp；这份长度表也可用于核对 BED 是否超出边界。两家发布的 FASTA 虽对应 CHM13v2.0，命名、mask 和线粒体处理仍应逐一核对，不能仅凭组装名称推断字节完全相同。

怎样选？ UCSC 的 hs1/bigZips/ 提供 hs1.fa.gz，不提供名为 maskedY 的 FASTA。本文的 maskedY 专指 T2T 项目 assemblies/analysis_set/ 中的文件：它将 Y-PAR 写成 N。要提取该区原有碱基，可以用 UCSC hs1.fa.gz 或 T2T 未遮蔽的 chm13v2.0.fa.gz；新做 CHM13 短读长比对／变异检测，可把 T2T 推荐的 maskedY_rCRS 作为起点，再核对突变分析、注释和验证数据是否使用同一版本。HiFi／ONT 研究复杂区域可以比较 CHM13 和 GRCh38，但较长的 reads 并不会自动消除参考单倍型偏倚。 UCSC hs1/bigZips/：“Files”节 、T2T 项目 analysis_set/README.txt：“File descriptions” 、T2T 变异分析研究

MANE：选中了转录本，但是不意味着唯一的基因组定位

一个 MANE NM_... 是转录本编号，同一转录本可以在 primary、FIX、ALT 上有不同的基因组定位。这些定位不应误称为不同的剪接异构体。

NCBI 的 MANE v1.5 官方 summary 中，有 64 个基因的 MANE Select 注释在 genomic patch 上。以 SHANK3 为例：NCBI 说明主染色体序列的一处插入会使编码区移码，因此其 MANE Select 注释在 patch NW_015148969.2 上。chr22 上依然可能找到这个 NM 的另一种 UCSC 比对定位；“有 primary 定位”并不证明它比 FIX 更适合提取准确的 MANE 编码序列。 NCBI MANE：patch 上的转录本

另外，我还发现有16个NM_ 的转录本只有 FIX 定位，没有 primary 或 ALT 定位。这 16个转录本是上述 64 条官方 patch MANE 的子集。在我核对的 MANE v1.5 与 UCSC 转录本数据快照中，64 条的定位分布是：只有 FIX 16、只有 ALT 29、primary + FIX 16、primary + ALT 1、ALT + FIX 1、primary + ALT + FIX 1。NCBI MANE：“MANE Select on genomic patch sequences”节

64 条 MANE patch 转录本的完整定位表 放在独立文件中；正文先看几个能说明不同定位情形的例子。

几个例子能说明为什么不能制定“所有基因只选 primary”或“所有基因只选 FIX”的规则：

  • ABO — NM_020469.4：官方 MANE patch accession 为 NW_009646201.1；该 UCSC 数据库中的对应定位只有 chr9_KN196479v1_fix。GRC 也用 ABO 说明 FIX 如何纠正原主染色体位点的组装路径问题。GRC patches：“What types of patches are there?”中的 ABO 图例
  • SHANK3 — NM_001372044.2：该库可见 chr22 和 chr22_KQ759762v2_fix。是否有 primary 定位，与哪个定位能准确代表 MANE 序列，是两个不同问题。NCBI 的 SHANK3 说明
  • HLA-DRB3 — NM_022555.4：该库可见三个 chr6_..._alt 定位。研究或设计 HLA 时，应明确是需要特定单倍型，还是要同时覆盖多种单倍型。
  • PRAMEF22 — NM_001100631.2：该库可见一个 ALT 和一个 FIX，没有 primary。

基因组目标设计还会遇到不在这 64 条中的多定位转录本。MCPH1 的 NM_024596.5 是一个特别能说明问题的例子：MANE v1.5 官方位置是主染色体 NC_000008.11:6406627-6648508。本地 UCSC 转录本库还给出两条 FIX 上的局部比对；它们不是两份可替换整条 MANE 转录本的序列。MANE v1.5 官方 summary

NM_024596.5 的定位 该库可见的 exon patch 的实际背景
primary chr8 14 个，覆盖整条 MANE 转录本 官方 MANE 所选定位。
chr8_KZ208915v1_fix 仅 5 个局部编号的 exon 约 6.37 Mb 的 H2 单倍型组装路径，含相对 GRCh38 约 4.2 Mb 的倒位，并关闭两个缺口。
chr8_MU273362v1_fix 仅 11 个 exon 一条约 430 kb 的 patch，修正主染色体组装组件中约 2 kb 的倒位错误。

两个 FIX 修正的问题和覆盖范围都不同。GRC HG-76：“Resolution”与“Patches and alternate loci”节 、MU273362.1 的 GenBank COMMENT 给出了各自的组装背景。更关键的是，本地 p14 FASTA 的实际序列对照显示：KZ patch 上标作“exon 1”的片段只有 10 bp，并不是 primary 上 63 bp 的 exon 1；其局部 exon 4、5 分别与 primary 的 exon 13、14 完全一致。MU patch 的 exon 1 与 primary exon 1 完全一致，前 10 个同号 exon 也一致；它仍未覆盖全部 14 个 exon。可见，不同 scaffold 上的 exon 1 标签不一定指同一个转录本 exon。

如果目标是 MCPH1 整条 MANE 转录本、全部 exon 或完整 CDS，该库中只有 primary 给出完整的 14 个 exon，应以官方 MANE 的 primary 定位为基础。即使只做少数 exon，也应先按转录本序列及注释确认 patch 片段对应的是 primary 的哪个 exon，再判断该 patch 是否改变目标碱基或单倍型表示。对于 primary exon 1，KZ 的局部“exon 1”不能当作候选；MU 的 exon 1 与 primary 序列相同，单凭它位于 FIX 上不足以要求重复设计。若目标本来就是两条 patch 所修正的结构区域，则应另外按具体 patch 坐标和实验目的设计，不能机械套用“FIX 优先”。

64 条之外，还有多少 ALT／FIX 定位？

并不少。在同一份本地 UCSC 转录本数据库中，19,293 条 MANE Select NM_ 里，去掉上述官方选在 patch 上的 64 条后，还有 1,522 条 能查到 primary 以外的附加定位：831 条 primary + ALT，603 条 primary + FIX，88 条 primary + ALT + FIX。其余 17,707 条在该库只查到 primary。这个快照中，官方 64 条之外没有仅 ALT 或仅 FIX 的 MANE Select NM；另外 1,522 条都仍有 primary 定位。这里统计的是同一 NM 的可见比对位置类别，不是 1,522 条 MANE 被官方改选到 patch，也不是建议对每个基因同时设计所有 scaffold；版本和注释来源变化后数字也会变化。

独立表格列全 64 条官方 patch MANE；其余 1,522 条数量较多，在正文给出统计和典型例子。下面几条并不在官方 64 条之内，却说明了多定位的不同形态（数量是该数据库对相应 NM 可见的不同 scaffold 数）：

基因 MANE Select NM 本地可见的定位 需要留意的地方
CYP2D6 NM_000106.6 primary + 5 条 ALT 复杂拷贝数及单倍型区域；不能把每条 ALT 当作独立基因。
HLA-A NM_002116.8 primary + 3 条 ALT 探针设计可能需要考虑多个单倍型，而普通比对需 ALT-aware 处理。
HLA-C NM_002117.6 primary + 5 条 ALT 不同 ALT 是局部替代序列，不能与 primary 坐标直接合并。
CHRNA7 NM_000746.6 primary + 2 条 ALT + 1 条 FIX 三类定位都在，先核对具体目标的完整性和用途。
SMN2 NM_017411.4 primary + 1 条 ALT + 1 条 FIX 同时有替代表示与修补序列，不能只凭类别自动决定唯一目标。
MCPH1 NM_024596.5 primary + 2 条 FIX 两条 FIX 都只覆盖转录本的一部分，且局部 exon 编号不能直接互比；见上面的实例。

这些 NM 是从 MANE v1.5 官方 summary 的 RefSeq_nuc 列 核对的；额外 scaffold 的数量来自前述 UCSC 转录本数据库快照。候选定位的存在不等于该定位对所请求的每个 exon、CDS 或整基因目标都完整。

实际提取时，建议依次确定：转录本版本、需要的 exon／CDS、候选定位、所需 exon 在各定位是否完整、所选 FASTA 的 .fai 是否含该 scaffold，以及最终使用的坐标制式。FIX scaffold 上的坐标属于 FIX 自己，不能直接塞进主染色体坐标的 VCF。 GRC patches：“How should I refer to patches in a publication?”节

任务二：短读长及长读长测序数据应比对到哪一套参考？

比对器需要在整套 FASTA 中为 read 找位置。高度相似的 ALT／FIX 与 primary 并列时，普通比对可能产生多个候选位置和低 MAPQ，影响后续变异检测；缺少适当的 unplaced 或 decoy 序列时，也可能让部分 reads 错落到主染色体。两种影响都应考虑。 GATK：“GRCh38 ALT contigs”节 、GRC patches：“What implications do patches have for my analyses?”节

分析情形 合理起点
复现已有 BAM／CRAM、VCF 或临床流程 使用与原流程完全配套的 FASTA、注释和资源；核对序列名、长度及校验值。
新的常规 GRCh37 短读长分析 hs37d5 是常见选项；是否采用 decoy 还要服从下游流程。
新的常规 GRCh38 短读长分析 hs38／GRCh38 no-alt analysis set 是稳妥起点；UCSC hg38.analysisSet.fa.gz 也是这类文件。
明确需要 hs38d1 decoy 选择 no_alt_plus_hs38d1 并使整条流程使用同一参考。
HLA／KIR 等 ALT 单倍型是目标 使用经验证的 ALT-aware 流程、专用分型方法或适合该任务的多参考方法。
PacBio HiFi／ONT 分析 根据变异检测工具、注释和研究区域在 GRCh38 no-alt 与 CHM13 之间选择；复杂区域可单独评估 CHM13。

Li Heng 的 参考选择文章 及后续 ref-gen 仓库 推荐 GRCh37 的 hs37d5 和 GRCh38 的 no-alt 分析集。仓库中的 hs38DH 含 ALT、decoy 和额外 HLA 序列，并非 NCBI full_plus_hs38d1 的同义文件；通常需要相应的 ALT-aware （做alignment的程序要能理解和使用alt序列）处理。既有 1000 Genomes GRCh38 数据可能采用另一套包含 ALT 的配套参考，复现时必须以原项目的实际文件为准。 1000 Genomes 的参考组装说明

长读长能改善许多重复和复杂区域的解析，却不会让参考选择变得无关紧要。PacBio 为 HiFi 工具生态主要提供一套经过修改的 GRCh38 no-alt 参考，也提供 CHM13 以研究 GRCh38 表示不佳的区域。T2T-CHM13 能增加以前缺失或组装不佳区域的可分析性，但换组装时注释、变异资源、基准集和结果坐标必须一同切换。 PacBio 参考基因组项目 、T2T 变异分析研究

PAR mask 是遮蔽什么？

X 与 Y 的 PAR1、PAR2 是同源区域。若参考中同时保留两份近乎相同的可比对序列，一些 reads 无法稳定归属。GRCh38 analysis set 将 Y 上的 PAR 硬遮蔽为 N，让常规流程把相应 reads 主要放在 X 的 PAR 坐标；T2T 也提供 maskedY 文件。这里的倍性仍须由下游根据样本和区域正确处理，不能仅靠 mask 自动解决。 GATK：“Pseudo-autosomal regions”节 、T2T analysis_set/README.txt：“File descriptions”

Soft mask 只是把部分碱基写成小写，碱基本身仍在；hard mask 则把指定碱基改为 N。若任务是提取 Y-PAR 的真实碱基，不能从已经把该区写成 N 的 analysis set 提取。 NCBI 对两类 masking 的说明

怎样才能明确定义所用的基因组而不搞混

不要只写“使用hg38/hg19”。一般不要直接用hg19，无论是提取序列（应该用hg19.p13.plusMT.fa)，还是做alignment（hs37d5更好）都不合适。使用的时候，至少记录 FASTA 的准确文件名、是否包含 ALT／FIX／decoy、mask 方式、序列命名、注释版本。从已有 BAM／CRAM 提取序列或继续分析时，还要与文件中的参考序列字典核对。SAM 的 @SQ 可记录每条序列的名称、长度和序列 MD5，能够识别“名字相似、碱基不同”的情况。 SAM 格式规范 、GATK 的参考兼容性说明

按 BED 提取序列时，再检查一次坐标：BED 是 0-based、半开区间；常见 samtools faidx chr:start-end 区域写法采用 1-based 位置。例如 BED 的 chr1 100 200 对应 chr1:101-200。 HTSlib FASTA 索引说明 、Samtools 对 BED 坐标的说明

结论：提取序列时让 FASTA 服从坐标和定位；比对 reads 时让 FASTA 服从完整分析流程。 两项工作可以选择不同文件，但每份结果都应能追溯到实际使用的参考序列。

UCSC 文件用 rsync 下载更方便

UCSC 的 bigZips 同时提供网页目录和 rsync 服务。将下面地址中的 rsync:// 改为 https://，即可在浏览器查看目录；用 rsync 下载时，可以反复执行同一命令来同步文件。rsync 默认用大小和修改时间快速判断未变化的文件并跳过；-P 会显示进度并保留中断时的部分文件，便于继续传输。对于已经压缩的 .gz，示例命令不额外开启传输压缩。下载后的完整性仍可按目录中的 md5sum.txt 核对。 UCSC hg38 README.txt：“How to Download”节的 rsync 示例 、rsync 手册：quick check 与 -P
